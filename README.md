# Offsetkey ZMK Config

ZMK firmware configuration for the Offsetkey split keyboard with dongle architecture.

## Hardware Overview

The Offsetkey is a three-piece wireless split keyboard:

| Piece | Role | Key Count | Special Hardware |
|-------|------|-----------|------------------|
| **Left half** | BLE peripheral | 5x7 matrix + 6 direct | EC11 rotary encoder, SSD1306 128x32 OLED, WS2812 RGB x10 |
| **Right half** | BLE peripheral | 5x10 matrix + 6 direct | PMW3610 trackball, SSD1306 128x32 OLED, WS2812 RGB x10 |
| **USB dongle** | BLE central | None (mock kscan) | SH1106 129x64 OLED (Bongo Cat), WS2812 RGB x10 |

All three pieces run on the **eyelash_nano** board (nRF52840). The dongle connects to the host via USB and communicates with both halves over BLE. The trackball on the right half is relayed through BLE to the dongle and then to the host.

## Keymap

![Diagram of config/offsetkey.keymap](keymap-drawer/offsetkey.svg "generated by @caksoylar's Keymap Drawer")

### Layer Summary

| Layer | Name | Encoder Function | Notes |
|-------|------|-----------------|-------|
| 0 | BASE | Scroll (mouse wheel) | Standard QWERTY with trackball mouse |
| 1 | LOWER | Volume Up/Down | F-keys, numpad cluster, media controls |
| 2 | MOUSE_KEYS | Volume Up/Down | RGB controls, BLE profile select, anti-idle toggle |
| 3 | MOUSE_TP | CPI Up/Down | Trackball settings -- scroll keys, middle click, CPI adjustment via encoder |

Access Layer 3 via combo: Left Fn + Right Fn (toggle).

## Building

### Local Build

Requires a Zephyr toolchain with `west` and the project's Python virtual environment.

```bash
# Build all three pieces
./build-local.sh all

# Build individual pieces
./build-local.sh left
./build-local.sh right
./build-local.sh dongle
```

Output firmware files:
- `build_left/zephyr/zmk.uf2`
- `build_right/zephyr/zmk.uf2`
- `build_dongle/zephyr/zmk.uf2` (includes ZMK Studio support)

The dongle build automatically enables ZMK Studio (`-DCONFIG_ZMK_STUDIO=y`) for web-based keymap editing.

### CI Build

Push to the repository triggers a GitHub Actions workflow (`.github/workflows/build.yml`) that uses ZMK's official `build-user-config.yml` reusable workflow.

## Directory Structure

```
zmk-config-offsetkey/
|-- config/
|   |-- west.yml                  # West manifest (ZMK + third-party modules)
|   |-- offsetkey.keymap           # Keymap definition (all layers)
|   |-- offsetkey.conf             # Global Kconfig (BLE, display, RGB, trackball)
|   +-- offsetkey.json             # ZMK Studio metadata
|
|-- boards/shields/offsetkey/      # Shield definitions
|   |-- offsetkey.dtsi             # Base: matrix transform, encoder, backlight
|   |-- offsetkey_peripheral_left.overlay
|   |-- offsetkey_peripheral_right.overlay
|   |-- offsetkey_central_dongle.overlay
|   |-- trackball.dtsi             # PMW3610 SPI1 config
|   |-- trackpoint.dtsi            # PS/2 trackpoint (disabled, alternative)
|   |-- split_input_common.dtsi    # Trackball BLE relay + input transforms
|   |-- rgb.dtsi                   # WS2812 LED strip SPI3 config
|   |-- offsetkey_physical_layout.dtsi  # Key positions for ZMK Studio
|   |-- Kconfig.shield / Kconfig.defconfig / *.conf
|   +-- boards/eyelash_nano.overlay
|
|-- zmk-offsetkey-status/          # Custom module: peripheral OLED status screen
|   |-- src/status_screen.c        # Connection dot + battery bar + animation
|   +-- src/frames.h               # Superloop animation frames (8 frames)
|
|-- zmk-pmw3610-cpi/               # Custom module: trackball CPI adjustment
|   |-- src/behaviors/behavior_pmw3610_cpi.c
|   |-- dts/behaviors/pmw3610_cpi.dtsi
|   +-- include/dt-bindings/zmk/pmw3610_cpi.h
|
|-- build-local.sh                 # Local build script
|-- keymap-drawer/                 # Generated keymap SVG
+-- docs/                          # Documentation
    |-- MODULES.md                 # Custom and third-party module guide
    +-- SHIELDS.md                 # Shield definition and hardware guide
```
